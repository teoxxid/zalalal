# План тестового покрытия приложения VoltMarket

## Критерии выбора сценариев для тестирования

Тесты написаны для сценариев, которые:
1. **Часто используются пользователями** (получение списка услуг, авторизация)
2. **Могут привести к потере данных** (создание/удаление заказа)
3. **Связаны с правами доступа** (просмотр чужих заказов)
4. **Влияют на деньги** (расчёт стоимости заказа)
5. **Содержат сложную логику** (фильтрация, валидация)

## Сущности приложения и приоритеты тестирования

| Сущность | Критичные сценарии | Приоритет | Тип теста | Покрыто в лабе |
|----------|-------------------|-----------|-----------|---------------|
| **User** | Регистрация, авторизация, смена роли | Высокий | Integration + Unit | Авторизация |
| **Service** | Создание, фильтрация, получение детали | Высокий | Integration + Unit | Фильтрация + деталь |
| **Order** | Создание, добавление товара, расчёт суммы | Высокий | Integration | Добавление товара |
| **OrderItem** | Уникальность пары (order, service) | Средний | Unit | Валидация уникальности |
| **Auth** | Проверка прав (модератор/пользователь) | Высокий | Integration | Не покрыто (в плане) |
| **Cart** | Иконка корзины, подсчёт товаров | Средний | Integration | Не покрыто (в плане) |

## Типы тестов и их назначение

### Unit-тесты (`pytest -m unit`)
- **Что тестируют:** Отдельные функции, валидацию моделей, расчёты
- **Запуск:** При каждом коммите (быстро, < 10 сек)
- **Примеры:** 
  - Валидация длины названия сервиса
  - Расчёт общей суммы заказа
  - Проверка уникальности пары (order, service)

### Integration-тесты (`pytest -m integration`)
- **Что тестируют:** Взаимодействие API + БД, полные сценарии
- **Запуск:** Перед слиянием в main / перед сдачей (1-2 мин)
- **Примеры:**
  - Создание заказа через API
  - Фильтрация услуг с параметрами
  - Проверка прав доступа к заказам

### Smoke-тесты (`pytest -m smoke`)
- **Что тестируют:** Критические пути ("приложение живо?")
- **Запуск:** После деплоя, в CI/CD (быстро, < 30 сек)
- **Примеры:**
  - Ответ `/api/services/` → 200 OK
  - Авторизация с верными данными → 200
  - Авторизация с неверными → 401

### Regression-тесты (`pytest`)
- **Что тестируют:** Вся функциональность, чтобы не сломать старое
- **Запуск:** Перед релизом / сдачей лабораторной (5-10 мин)
- **Состав:** Все unit + integration + smoke

## Группировка тестов

| Группа | Маркер pytest | Что включает | Когда запускать |
|--------|--------------|-------------|----------------|
| **unit** | `-m unit` | Валидация, расчёты, изолированная логика | При каждом изменении кода |
| **integration** | `-m integration` | API + БД, сценарии пользователя | Перед коммитом / PR |
| **smoke** | `-m smoke` | Health checks, auth, critical paths | После деплоя, в CI |
| **regression** | (все тесты) | Полный набор | Перед сдачей / релизом |
| **auth** | `-m auth` | Тесты авторизации и прав | При изменении auth-логики |
| **services** | `-m services` | Тесты сущности Service | При изменении каталога |
| **orders** | `-m orders` | Тесты заказов и корзины | При изменении логики заказов |

## Сценарии, не покрытые тестами (и почему)

| Сценарий | Почему не покрыт | План покрытия |
|----------|-----------------|--------------|
| Загрузка файлов в MinIO | Требует мокания S3-клиента, сложно изолировать | Добавить в лабу 7 (если будет время) |
| WebSocket-уведомления | Асинхронная логика, требует отдельного тестового окружения | Вынести в отдельный модуль тестов |
| Пагинация больших списков | Требует генерации 1000+ тестовых записей | Добавить параметризованные тесты |
| Кэширование (Redis) | Тесты кэша требуют отдельной конфигурации | Добавить тесты с `@override_settings(CACHES=...)` |

## Как запускать тесты

```bash
# Все тесты (регрессия)
pytest

# Только unit-тесты (быстро)
pytest -m unit

# Только integration-тесты (проверка БД)
pytest -m integration

# Smoke-тесты (проверка "живости")
pytest -m smoke

# Тесты конкретной сущности
pytest -m services
pytest -m orders

# С отчётом о покрытии (откроется htmlcov/index.html)
pytest --cov=main --cov-report=html

# Один конкретный тест
pytest tests/integration/test_services_api.py::TestServiceListAPI::test_get_services_list_success
